# Развёртывание в production и восстановление

Это подробное русскоязычное руководство по разворачиванию мода amp-autocert.
Английская версия: [`PRODUCTION_SETUP.md`](PRODUCTION_SETUP.md).

Руководство применимо только к Minecraft 1.21.1, NeoForge 21.1.248 и проверенным
версиям AutoModpack из диапазона `[5.0.0-rc.1,5.0.0-rc.2]`. Эталонное
развёртывание 29.09.2026 включало реальный production-выпуск Let's Encrypt,
очистку DNS-01 записей Cloudflare, ротацию учётных файлов, активацию через
AutoModpack 5.0.0-rc.2, сохранение сертификата после перезапуска и проверку
доверия на клиенте. Каждая новая установка обязана пройти собственный
контролируемый rollout; production-режим никогда не включён по умолчанию.

## 0. Сборка мода из исходников

1. Установите **JDK 21** и Git.
2. Клонируйте репозиторий и откройте папку проекта:
   `git clone https://github.com/MihailDenisov/amp-autocert.git`
3. Первый запуск требует интернет: лаунчер скачивает официальный Gradle
   8.14.3 wrapper JAR и проверяет его опубликованный SHA-256, затем Gradle
   скачивает зависимости NeoForge.
4. Сборка: `./gradlew build` (Windows: `gradlew.bat build`).
   Готовый JAR появится в `build/libs/`.
5. Тесты: `./gradlew test`. Офлайн-проверка без сети:
   `sh scripts/offline-smoke-test.sh` (нужны JDK 21 и POSIX shell).
6. Установите полученный JAR в папку `mods/` выделенного сервера вместе с
   поддерживаемой версией AutoModpack (`automodpack_mod`,
   `[5.0.0-rc.1,5.0.0-rc.2]`). Без AutoModpack или с другой его версией
   NeoForge отклонит запуск — это намеренная защита.

## 1. Требования к DNS и сети

- `play.maicraft.tech` — адрес, который вводят игроки.
- `_minecraft._tcp.play.maicraft.tech` указывает на `hm.maicraft.tech:25598`.
- `hm.maicraft.tech` резолвится напрямую в публичный адрес Minecraft-сервера.
- AutoModpack объявляет endpoint `hm.maicraft.tech:25809`.
- Сертификат содержит `maicraft.tech` и `*.maicraft.tech`; wildcard покрывает
  и `play.maicraft.tech`, и `hm.maicraft.tech`.

Записи A/AAAA для `hm.maicraft.tech` держите в режиме **DNS only** (серое
облако). HTTP-прокси Cloudflare не является прозрачным прокси для порта
Minecraft и TCP-endpoint AutoModpack. Удалите устаревшую AAAA-запись, если
сервер фактически недоступен по IPv6. DNSSEC для DNS-01 не требуется.

## 2. Создание ограниченного токена Cloudflare

Создайте в Cloudflare отдельный custom API token:

- разрешение: `Zone / DNS / Edit`;
- ресурс: только конкретная зона `maicraft.tech`;
- никакого доступа ко всему аккаунту или другим зонам.

Ограничение по IP клиента полезно только при стабильном исходящем публичном
IP игрового сервера. ID зоны уже есть в публичном конфиге мода, поэтому
глобальный API-ключ и широкие разрешения на список зон не нужны.

Передайте токен ровно одним из способов:

1. Предпочтительно: переменная окружения контейнера
   `AMP_AUTOCERT_CF_API_TOKEN`.
2. Иначе: только текст токена в файле
   `automodpack/credentials/amp-autocert-cloudflare-token.txt`.

Никогда не помещайте токен в `amp-autocert.properties`, `server.conf`,
команду запуска, JAR мода, Git или логи для поддержки. На обычном
Linux-хостинге файл токена должен быть доступен только серверному процессу.
Если Pterodactyl не позволяет ни переменные окружения, ни смену прав,
явный запасной вариант описан в разделе 4.

## 3. Исключение всего приватного из AutoModpack

В каждой группе `automodpack/server.conf` добавьте оба пути в список
`exclude` этой группы:

```text
automodpack/credentials/**
automodpack/amp-autocert.properties
```

Одновременно проверьте все правила `from-server`. Широкое правило не должно
отдавать клиентам директорию с учётными данными, публичный конфиг, токен,
состояние ACME-аккаунта, журналы транзакций, бэкапы, сертификат или приватный
ключ. Эти исключения — обязательная защита в глубину, хотя поддерживаемые
AutoModpack rc.1/rc.2 обычно собирают группу из каталога host-modpack и явных
записей `from-server`.

Не вставляйте полный `server.conf` или токен в публичные issue. Два шаблона
исключений сообщать безопасно, если убрать остальные приватные пути.

## 4. Безопасная настройка amp-autocert

Скопируйте `config/amp-autocert.properties.example` в
`automodpack/amp-autocert.properties`. Проверьте как минимум эти значения:

```properties
enabled=false
debugmode=false
acme.environment=staging
acme.allowStagingIssuance=false
acme.domains=maicraft.tech,*.maicraft.tech
dns.zoneName=maicraft.tech
dns.challengeRecord=_acme-challenge.maicraft.tech
dns.propagationInitialDelaySeconds=15
dns.dohResolvers=https://cloudflare-dns.com/dns-query,https://dns.google/resolve
cloudflare.zoneId=YOUR_ZONE_ID
minecraft.hostname=play.maicraft.tech
minecraft.srvTarget=hm.maicraft.tech:25598
automodpack.endpoint=hm.maicraft.tech:25809
host.restartAfterRenew=true
```

Официальные HTTPS-endpoint'ы ACME и Cloudflare не меняйте. Значения по
умолчанию — окно продления 30 дней, интервал проверки 24 часа, сохраняемый
cooldown попыток 48 часов и ограниченный экспоненциальный retry — подходят
как стартовые. Cooldown резервируется перед production-order, включая
неудачный, чтобы не создать шторм запросов и не упереться в rate-limit.

Держите `debugmode=false` в обычной работе. Временное `debugmode=true`
добавляет безопасную диагностику фаз, hostname/status/latency каждого
resolver'а, количество TXT, тайминги retry, consensus и cleanup/recovery.
Оно никогда не включает сырые ACME/JWS/DNS-ответы сторонних библиотек и не
журналирует значения challenge, API-токены, состояние аккаунта, байты
сертификата или приватные ключи. После диагностики верните `false`.

Два переключателя совместимости с Pterodactyl ослабляют конфиденциальность
файлов и должны включаться только явно:

- `credentials.allowInsecureTokenFilePermissions=true` допускает права на
  чтение вроде `0644` для фиксированного файла токена. Симлинки, слишком
  большие файлы и доступ на запись для группы/остальных по-прежнему
  отклоняются.
- `credentials.allowInsecureDeploymentFilePermissions=true` запрещает моду
  вызывать chmod или менять ACL при установке сертификата. Записываемые
  группой/остальными пути не разрешаются.

Используйте эти переключатели только когда панель не даёт более безопасного
варианта. Ограничьте доступ к панели, бэкапам, консоли и SFTP доверенными
администраторами.

## 5. Резервная копия перед первой production-попыткой

При остановленном сервере сделайте приватную копию всей директории
`automodpack/credentials/`. Храните её вне всех групп AutoModpack и вне
хранилищ, доступных извне. Там могут быть активный приватный ключ, ключи
ACME-аккаунта, файл токена Cloudflare, состояние выпуска и данные
восстановления.

Никогда не копируйте и не восстанавливайте только один из файлов
`certificate.crt` и `private-key.pem` — это пара. Поддерживаемые AutoModpack
rc.1/rc.2 ожидают:

- `automodpack/credentials/certificate.crt`: полная PEM-цепочка, leaf первым;
- `automodpack/credentials/private-key.pem`: незашифрованный ключ PKCS#8 PEM.

## 6. Переход от staging к production

Сначала запустите сервер на Java 21 с:

```properties
enabled=true
acme.environment=staging
```

Используйте `/ampautocert status` и `/ampautocert check`. Убедитесь, что
отображаются нужная среда, текущий статус срока действия/SAN, работа
фонового worker'а и чистое завершение. `/ampautocert renew` в staging должен
отклоняться. Плановая staging-проверка этой сборки намеренно
**только наблюдает**: она не создаёт ACME-order.

Для отдельной контролируемой тестовой зоны настройте её пару apex/wildcard,
владельца challenge, имена хостов, zone ID Cloudflare и ограниченный токен
тестовой зоны. Затем установите `acme.allowStagingIssuance=true`,
перезапустите и выполните ровно один `/ampautocert staging-issue`. Команда
работает в фоновом worker'е, создаёт и удаляет только свои TXT-записи,
структурно проверяет полученный staging-материал в памяти и отбрасывает его.
Сохраняемый cooldown по среде не даёт повторять orders. Команда никогда не
записывает `certificate.crt` или `private-key.pem`, не перезапускает
AutoModpack и отклоняется в production. После упражнения верните `false`.

Перед включением production на новой установке завершите отдельное
упражнение в контролируемой тестовой зоне без production-токена и
production-домена. Оно должно продемонстрировать создание и очистку DNS-01
записей, валидацию сертификата, активацию AutoModpack, rollback, завершение
на Java 21, отказ при нехватке прав и отклонение NeoForge при отсутствии
AutoModpack, версии вне диапазона rc.1/rc.2 или несовместимом API.
В репозитории есть детерминированные тесты с заглушками, а эталонная
установка прошла один живой production-прогон; ни то, ни другое не заменяет
проверку другого сервера, токена провайдера, сети или конфигурации
AutoModpack.

Только после успешных проверок:

1. Остановите сервер и обновите приватный бэкап учётных данных.
2. Убедитесь, что AutoModpack — rc.1 или rc.2 и его хост настроен на
   внутренние TLS-файлы.
3. Убедитесь, что ограниченный токен Cloudflare доступен и оба шаблона
   исключений применены к каждой группе.
4. Измените `acme.environment=production`; оставьте `enabled=true` и
   `host.restartAfterRenew=true`.
5. Запустите сервер один раз. Не перезапускайте его повторно и не вводите
   `/ampautocert renew` подряд после неудачи.
6. Следите за серверным логом до финального (замаскированного) результата,
   затем выполните `/ampautocert status`. Проверьте production-среду,
   ожидаемый срок действия и развёрнутые SAN. Отдельно проверьте подключение
   игрока и подключение AutoModpack.

`/ampautocert renew` намеренно форсирует только решение о сроке действия.
Он не может обойти разделение staging/production, сохраняемый cooldown
production-попыток, совместимость AutoModpack, валидацию
сертификата/ключа/PKIX, однопоточное (single-flight) выполнение или rollback.

## 7. Ротация и поведение при откате

При продлении мод создаёт обе DNS-01 TXT-записи, когда авторизации apex и
wildcard пересекаются. Он отслеживает их record ID в Cloudflare и удаляет
только записи, принадлежащие этому order. Перед тем как трогать живую пару,
проверяются цепочка CA, точный набор SAN, покрытие имён хостов, срок
действия, назначение TLS server и соответствие ключа.

Новый ключ и сертификат сначала размещаются (stage) на целевой файловой
системе. Старая пара хранится в приватной транзакции, пока AutoModpack не
сообщит, что он запущен с точным SHA-256 fingerprint нового
leaf-сертификата. При сбое записи, валидации, перезапуска или проверки
готовности старая пара восстанавливается, где это возможно. Восстановление
после аварии выполняется до следующего решения о сертификате.

Аварийное ручное восстановление:

1. Установите `enabled=false` и остановите Minecraft.
2. Приватно сохраните неудачную/текущую директорию credentials для
   диагностики.
3. Восстановите полный бэкап `automodpack/credentials/` до изменений,
   включая парную пару сертификат/ключ; не смешивайте отдельные файлы
   транзакций.
4. Запустите Minecraft и убедитесь, что AutoModpack отдаёт
   восстановленный fingerprint.
5. Держите продление выключенным, пока идёт расследование. Не удаляйте
   DNS-записи, если точные record ID и владение неизвестны.

## 8. Существующие fingerprint-pin'ы AutoModpack

Публично доверенный сертификат избавляет новых клиентов от ручного ввода
fingerprint только когда сертификат покрывает используемый адрес и правила
доверия AutoModpack его принимают. Сохранённый игроком ручной pin имеет
приоритет над доверием к CA. Такому игроку может потребоваться один раз
удалить старый pin при миграции; продление сертификата не может молча его
переопределить.

## 9. Диагностика проблем

| Симптом | Действие |
| --- | --- |
| `acme.environment must be production` | Ожидаемая защита для `/ampautocert renew`; staging-пробу используйте только в контролируемой тестовой зоне. |
| Staging-выпуск не разрешён | Нужны одновременно `acme.environment=staging` и `acme.allowStagingIssuance=true`; после правки файла перезапустите сервер. |
| Нужна дополнительная диагностика | Временно включите `debugmode=true` и перезапустите. Не публикуйте `debug.log`: защищённые протокольные данные скрыты, но топология сервера может быть видна. |
| Токен отсутствует/не читается | Задайте `AMP_AUTOCERT_CF_API_TOKEN` или проверьте фиксированный файл. Никогда не печатайте токен для проверки. |
| Слишком широкие права на файл токена | Исправьте права в панели или явно включите только документированный fallback для Pterodactyl и ограничьте пользователей панели/SFTP. |
| NeoForge отклоняет отсутствующую/несовместимую зависимость `automodpack_mod` | Установите AutoModpack из `[5.0.0-rc.1,5.0.0-rc.2]`. Новые версии требуют проверки исходников и runtime, прежде чем диапазон будет расширен. |
| Хост AutoModpack не инициализирован | Проверьте собственную конфигурацию хоста AutoModpack и ошибки запуска; продление останется заблокированным вместо угадывания другого API. |
| `host.restartAfterRenew=false` | Устанавливайте `true` только после принятия интеграции перезапуска/готовности. |
| Действует production-cooldown | Ждите, пока `/ampautocert status` не покажет время следующей попытки; перезапуски и повторные команды его не сбрасывают. |
| Таймаут распространения DNS | Проверьте авторитетные серверы Cloudflare, точный zone ID, область токена и записи `_acme-challenge`. Не добавляйте постоянные TXT-записи как обходной путь. |
| Таймаут активации/готовности | Убедитесь, что внутренний TLS AutoModpack включён, порт 25809 настроен и endpoint не занят другим процессом. Старая пара должна сохраниться или быть восстановлена. |
| Сертификат всё ещё выглядит самоподписанным | Сначала проверьте статус и лог сервера. Не перезаписывайте только один файл из пары. Убедитесь, что клиенты достигают настроенного endpoint AutoModpack. |
| Клиент сообщает о несовпадении fingerprint | Удаляйте старый ручной pin клиента только после независимой проверки сервера и нового публичного сертификата. |

Логи и пакеты для поддержки не должны содержать токен, ключи ACME-аккаунта,
приватный ключ, сырые ответы Cloudflare, полную директорию credentials или
немаскированные настройки окружения панели.
